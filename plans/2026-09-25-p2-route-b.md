# Plan: P2 part 1 — Route B provisioning and the first end-to-end run (token-ring)

Goal: stand up the prover route (Route B) and prove it end-to-end on the token-ring task — the
*point* of the experiment. Concretely: provision Lean 4 + Mathlib in the dev shell, port token-ring's
`Mutex` as a Lean theorem (general + `N₀` corollary) with the committed equivalence audit, drive the
closure loop against a **real** prover and a **real** model, record the Route B row, and run the Route
B mutant as the negative control. This is `plans/2026-09-25-bootstrap.md` §P2 (step 2), protocol §2
(Route B), §8 (measurement procedure), §3/§11 decisions 1–3, 5, 7.

## Non-goals / deferred to later slices

- **The `R ≥ 5` measurement cells** (protocol §4.7) — the actual data collection. This slice proves
  the capability with a *single* positive run and a *single* mutant run; the repetition cells (pass
  rates, distributions) are the next slice ("P2 part 2 — measurement"), once the capability is trusted.
- **Bakery and EWD998 Route B.** Bakery Route A is not even calibrated yet (P1 close-out is still
  running), so its Route B model is a later slice.
- **The other P2/P3 tasks** (two-phase commit, LCR, cache coherence, …).
- **The general-tier headline analysis** (P4): reporting the verdict against decision 1.
- **Liveness** (protocol §11 decision 4): safety invariants only.

## Where the work stands (verified first-hand this session)

- `harness/closure.py` already runs the loop against a **port** — `Prover` (`start`/`goals`/`apply`/
  `unclosed`) and `Model` (`propose`/`usage`) protocols — and `run_loop(…)` returns a row with `route:
  "proof"`, `tier: 2`, `outcome`, `budget_exceeded`, `wall_clock_s`, `cost_usd`, `cost_basis`, and a
  `proof` object (`turns`, `unclosed_goals`, `input_tokens`, `output_tokens`, `model`, `tactics`).

  (§4.9), `assisted` (§11 decision 5), `resolvedModelIsFallback` (decision 2), or the mutant outcome
  (fail-to-close vs disproof, §5).
- `flake.nix` ships `tlaplus`, `python3`, `pytest`, `jq`, `z3` — **no Lean**. `proofs/` is empty.
- `harness/tlc_run.py` is the model for a subprocess driver: it spawns a child, times it, parses its
  stdout, and emits a row — the Route B prover driver follows the same shape (subprocess + JSON parse).
- Provisioning facts are settled in the bootstrap plan: `elan` from nixpkgs (`elan-4.2.4`); the Lean
  version comes from Mathlib's `lean-toolchain` (currently `leanprover/lean4:v4.35.0-rc3`), not
  nixpkgs' `lean4-4.30.0`; oleans are fetched with `lake exe cache get` (~407 MB) — a **network**
  step. Host auth: `deepseek/*` and `groq/*` authenticate; OpenAI/Anthropic keys are rejected (401).
- The bootstrap plan lists the closure interfaces: `lean-repl` (JSON `{"tactic", "proofState"}` in →
  `{"proofState", "goals"}` out), Pantograph (goal RPC, LeanDojo-v2), Kimina (FastAPI over lean-repl).

## Decisions

### D1 — Slicing

This slice = provisioning + first end-to-end Route B run on token-ring (positive **and** mutant) +
the equivalence audit + the new row fields. The `R ≥ 5` cells, and Bakery/EWD998/other-task Route B,
are later slices. Rationale: the capability must be proven trustworthy once (one success, one
mutant) before spending the ~10 h/cell measurement budget.

### D2 — Driver: `lean-repl`

The `Prover` port is implemented by a `LeanReplProver` that speaks the `lean-repl` JSON protocol over
a subprocess (stdin/stdout), mirroring `harness/tlc_run.py`'s subprocess shape. Rationale: it is the
simplest interface, it is the bootstrap plan's first choice ("lean-repl first"), and a JSON protocol
is trivial to script in a test. **Pantograph is the recorded fallback** if goal-state fidelity proves
insufficient (multiple/derived goals rendered ambiguously); switching is a plan change, not a silent
substitution.

**The `repl` binary (provisioning).** The `lean-repl` protocol is served by the `repl` executable from
`leanprover-community/repl`, which is **not in nixpkgs** and is not provided by `elan`. It is built as
a provisioning step: clone `leanprover-community/repl` at a pinned commit compatible with
`leanprover/lean4:v4.35.0-rc3` (the exact commit and toolchain recorded in `tools/repl/PROVENANCE.md`),
then `lake build` it against that same toolchain; the binary is `.lake/build/bin/repl` (a gitignored
build artifact). This is a **coder-run network/build step, not a scenario** (no test reaches the
network). The harness locates the binary via a `--repl-bin` path argument to `harness.route_b`
(mirroring `--tlc-bin`), defaulting to that built path. The driver spawns **`lake env <repl-bin>`**
with `cwd` = the proof project's directory (nearest ancestor of the proof file with a `lakefile`), so
the Mathlib oleans resolve for `TokenRing.lean`'s `import Mathlib`.

### D3 — Model: DeepSeek reasoning model (settled by the user), thinking level fixed and recorded

The loop's `Model` port is a DeepSeek client. **Settled (user, 2026-09-25): a DeepSeek reasoning
model** — one selector for the whole experiment (decision 2), thinking level fixed by the harness and
recorded per row.

**Where the selector and thinking level live.** A single config surface, never loop logic: module
constants in `harness/model.py` — `MODEL_SELECTOR` (the model id string) and `THINKING_LEVEL` — read
by `harness.route_b` and written verbatim into every row's `proof.model` and `proof.thinking`. Nothing
hard-codes a model id anywhere else.

**Concrete values (enumerated 2026-09-25).** `MODEL_SELECTOR = "deepseek-v4-pro"` — the provider id
exactly as `GET /models` returns it and the raw response's `model` field echoes (so the fallback
comparison is exact; a prefixed selector would flag every turn). Reachable ids were `deepseek-flash`
and `deepseek-v4-pro`; v4-pro's effective rates now match flash (since 2026-09-14), so it is the
strongest reasoning model at no cost premium. `THINKING_LEVEL = "high"` is **deliberate, not a
default**: the model's documented default, fixed for every run; `max` is reachable but declined (higher
token cost and a higher empty-content rate for a marginal proof-quality gain). `TEMPERATURE = 0.0` and
`MAX_TOKENS = 16384` were deliberate raw-client constants; **D20 supersedes the raw client**, so the
selector and thinking level become the `omp --model`/`--thinking` flags, and the recorded values are
those OMP reports per turn.

**`resolvedModelIsFallback` is compared against `MODEL_SELECTOR`.** Each provider response carries the
model id that actually served it; the harness records that string per response and sets
`resolvedModelIsFallback: true` when it differs from `MODEL_SELECTOR`. Fallback-served runs are
reported separately, never pooled (protocol §4.5).

**Enumeration caveat (do not discover at run time).** The coder must **not** type a model id from
memory. It must enumerate which `deepseek/*` ids this host's credentials actually reach, pick the
reasoning-capable one, record the provider's resolved model string per response, and treat any response
whose resolved model differs from the configured selector as a fallback turn. If the reasoning selector
is unreachable from this host, that is a **plan question back to the planner**, not a silent downgrade
to a chat model.

The model client is **network-bound and is never touched by a pytest scenario** — scenarios use the
`ScriptedModel`.

### D4 — Row fields (protocol §4.5/§4.6/§4.9/§5/§8)

`run_loop` and the Route B runner gain, on the returned row:
- `startup_s` — the prover's environment/olean load (recorded when the first goal state is ready),
  distinct from `wall_clock_s` and `proof_s` (§4.6);
- `auxiliary_invariants` — the human-supplied invariant statements (names + line/size) when any
  exist, else empty (§4.9);
- `assisted` — `true` iff a human supplied anything beyond the goal statement (§11 decision 5);
- `resolvedModelIsFallback` — set when a fallback model served any turn (§4.5);
- `tier` — `1` for the `N₀` corollary, `2` for the general theorem (§2); `mutant` handling below.
- `proof.failures` — the prover's verbatim rejection strings (exposed through a `Prover.failures`
  accessor), so a timeout row shows what the repl refused; `changed_declarations`/`missing_declarations`
  accompany `auxiliary_invariants` (D5).
- `artifacts.proof` — the (relative) proof-file path the driver wrote (`--artifact` is dropped: the
  artifact is `--proof`). `tool` carries `{"name": "lean", "toolchain": …, "repl": {"commit", "toolchain",
  "binary"}}` parsed from `tools/repl/PROVENANCE.md` (§4.4 tool version per row). `cost_basis` = the
  token-card basis plus a compute clause from `harness/result.py`.
These last shapes are coder-run-verified (a `/tmp` script + a recorded-row read-back), not scenario-pinned —
no pytest scenario reaches `route_b`.

### D5 — `assisted` is enforced structurally, not by discipline

The **seed is the proof file's content before the run** — the committed planner's theorem statement —
read by `route_b`; the driver works on that same file in place (no copy outside `proofs/lean/<task>/`,
which would break the lake package context, and **no `--artifact` flag** — the artifact is `--proof`).
After the loop, the harness parses the artifact's declarations — `theorem | lemma | def | abbrev |
instance | structure | class | inductive | opaque | example | macro | notation | syntax | axiom`,
tolerating leading modifiers (`private`/`protected`/`noncomputable`/`local`) and attributes (`@[…]`) —
and diffs each by **full body** (not the `:=` prefix) against the seed's, by name:

- an **extra** declaration (not in the seed) is a human-supplied invariant → `auxiliary_invariants` +
  `assisted: true`;
- a **changed type**, a **missing** declaration, or a changed **value** of a `def`/`opaque`/`abbrev` is a
  rewrite → `assisted: true`;
- a `theorem`/`lemma` body that changed `sorry` → a real proof is **faithful** → `assisted: false` (the
  statement is unchanged, §8).

This is enforceable because loop tactics cannot create top-level declarations (`have` is local). Pinned
by scenarios: the faithful `sorry`→script replacement stays `assisted: false`; `def Mutex : Prop :=
False` → `:= True` reports `assisted: true`. `detect_assisted` returns `{assisted, auxiliary_invariants,
changed_declarations, missing_declarations}` — `auxiliary_invariants` (extra declarations only),
`changed_declarations` (type/value rewrites), `missing_declarations` (seed declarations removed) — and
`assisted` is the OR of the three lists; a changed statement is recorded, never raised. Declarations are
accepted at **any indentation** (styling, never a semantic boundary); the same full-body comparison is
used for the artifact diff *and* the seed-side (seed-vs-baseline) check, so an added/changed declaration
of **any kind** in the seed is human work → `assisted`. `detect_assisted(older, newer, human=True)` takes
a `human` flag that is the provenance: `human=True` (baseline-vs-seed) marks an extra declaration
`assisted: true`; `human=False` (seed-vs-artifact) records the loop's own guessed helpers as
`assisted: false` (D19's invited-guess labelling).

### D6 — the artifact's closure is asserted, never trusted

The harness asserts the final artifact contains **zero** of `sorry` / `sorryAx` / `admit` / `Admitted` /
`axiom` (word-boundary) and **zero `?ident` metavariables** (Lean's synthetic-sorry hole) — every spelling
of an unclosed goal (protocol §8) — and that the goal statement is unchanged. `count_unclosed` is **comment- and string-literal-aware**: `/- … -/` block
comments, `-- …` line comments, and string literals are stripped before counting, so a `sorry` mentioned
only in prose counts zero. The driver's close-guard is part of this: a `goals: []` response is **only**
closure when the repl reports `proofStatus: "Completed"`; the repl's `sorry` shape is `goals: []` with
`proofStatus: "Incomplete: contains sorry"`, which the driver must reject (`unclosed > 0`). A genuinely
unclosed artifact records an `error` row with `artifact_unclosed_goals`, never a raised exception that
loses the row. Pinned by scenarios (a comment-only `sorry` → 0; the driver's close-guard by a scripted
repl responder).

### D7 — Route B mutant and the refutation arm (protocol §5)

`proofs/lean/token-ring/TokenRingMutant.lean` is the same model with the token-holding guard dropped
(the analogue of `TokenRingMutant.tla`). A Route B run that reports `success` on the mutant is broken
and its numbers are discarded (§5). `proof.tactics` records only **applied** steps; the mutant seed is
never overwritten (a closing run aborts before the write).

**The refutation arm (supersedes the dropped `disproof` branch).** Route B runs a **refutation arm
racing the proof arm under one budget** (D16): the arm proposes *refutations* — an explicit violating
witness, an enumeration over a bounded instance, or a proof of the negated statement — submitted
through the repl's **`cmd` channel**, the only channel through which `#eval`/`#reduce`/`decide`-style
search runs. A refutation is accepted only when **Lean accepts it** (the negated statement closes, or
the `cmd` output exhibits a reachable state violating the property), never on the model's say-so. For
the mutant the expected outcome is `refuted` (an informative success, not a budget burn); the
vacuousness guard is the mirror — a refutation produced against a statement TLC says holds is a rig
defect that fails loudly.

### D8 — Result-row file naming (resolved)

`results/proof.jsonl` is authoritative: Route B rows are written by `append_row(results_dir, "proof",
row)` (the `route` value `closure.py` already uses, and §2 names Route B "proof"). The stale
`results/lean.jsonl` in `docs/protocol.md` §6a is fixed to `results/proof.jsonl` so schema, plan and
protocol agree. "proof" (the route's method name) is chosen over "lean" (the tool) because §2's own
name for the route is "proof", and the file name must stay correct if the prover ever changes.

### D9 — Equivalence audit (protocol §4.1)

`docs/equivalence-token-ring.md` records the line-correspondence table between the TLA+ reference
semantics (`specs/tla/token-ring/TokenRing.tla`) and the idiomatic Lean model, statement by statement,
plus the general theorem and the `N₀` corollary, and states that the Lean model neither strengthens an
assumption nor weakens the goal. The audit is data (pinned by a contract), written once the model
exists.

### D10 — Run-cell sequencing (protocol §4.4: no concurrent load)

Measurement rows must be taken on an unloaded host, and Route A/B measurements never overlap:

- **This slice's Route B capability runs** (one positive, one mutant) run **after P1's `N = 23`
  calibration completes** and with no concurrent TLC, so `startup_s` (the ~32 s cold olean load) is
  measured unloaded.
- **Route A `N₀` cell = one row**, not `R ≥ 5` (deterministic with `-workers 1`; the N = 3
  five-identical-rows run already discharged the determinism check — the repetition budget belongs to
  Route B). Route A and Route B run cells are serialized, never concurrent, never interleaved.
- **Tier ordering**: after the tier-2 run closes `mutex`, **promote** it — copy the closed artifact over
  the committed seed, re-pin `seeds.json` + `baseline/<file>` to the closed text, and `lake build` —
  then run tier-1, so its import of the now-proven `TokenRing` passes D13's guard and its `assisted`
  stays `false`.

### D11 — Provider-quirk handling (empty content) and `max_tokens`

- **Empty content** (a reasoning model can return `finish_reason: stop` with everything in
  `reasoning_content` and empty `content`). The model client returns the empty content as an empty
  tactic rather than raising; `run_loop` treats it as a consumed, billed turn (counted, usage summed)
  and re-asks the same goals **with a nudge** ("you returned no tactic; propose one for the current
  goals"). There is **no consecutive-empty abort**: the budget (wall-clock / $) is the only terminator
  besides success, so a model that never answers is `timeout`, not `error`. Pinned by a scenario.
- **`max_tokens`** is a deliberate module constant `MAX_TOKENS = 16384`, recorded per row as
  `proof.max_tokens`; the empty-content retry above covers the case where reasoning consumes the
  budget and no content is emitted.
- **The wall-clock cap is checked between turns, not a hard interrupt**: a single turn (provider call
  with retries + a repl step) can overshoot the cap; `wall_clock_s` records the honest elapsed, and
  `budget_exceeded: "wall_clock"` means the cap was observed exceeded between turns, not that the run
  was interrupted mid-turn.

### D12 — Provider-failure semantics (mid-run)

A provider failure in the middle of a run must land a row, never lose the budget:

- **Abort + record (no retry):** `401` / `402` / other `4xx` — the model client raises
  `ProviderError(status, message)`; `run_loop` catches it and returns `outcome: "error"` with
  `error == {"kind": "provider_failure", "status": <int>, "message": <str>}`, the turns/tokens/cost
  **actually consumed** so far, and the partial artifact kept. The run is an outcome, not a result
  (§2); a mid-run 402 must not silently waste the budget.
- **Bounded retry:** `429` and `5xx` are transient — the client retries up to
  `MAX_PROVIDER_RETRIES = 3` (with backoff), not billed as turns; if still failing it raises
  `ProviderError` as above.
- **Consume-a-turn vs abort:** an empty-content response consumes a turn and re-asks (D11); a failed
  (non-`2xx`) call does **not** consume a billed turn — it either retries (`429`/`5xx`) or aborts
  (everything else, or retries exhausted). Pinned by a scenario.
- **Prover-side failure:** a `LeanReplError` from `prover.start()`/`prover.apply()` (step timeout, repl
  exit, non-JSON answer, seed that does not load) is caught the same way — `outcome: "error"` with
  `error == {"kind": "prover_failure", "message": <str>}`, the consumed turns/tokens/cost, and the
  partial artifact kept, loud exit code. The budget is the only *intended* terminator besides success;
  a prover failure is an error, never a lost row.

### D13 — Import-clean guard (a tier-1 run must not rest on a `sorry`-proved import)

A run closes a theorem over the repl's syntactic verdict on the *current* command; a `sorry` inside an
imported theorem's value is invisible to that check, so a tier-1 run could report `success` while
`mutex_n0` rests transitively on the imported `mutex`'s `sorryAx`. The guard is mechanical, not
procedural:

- `route_b` parses the seed's `import` statements, resolves the **project-local** ones (under
  `proofs/lean/`), and **refuses** (loudly, no row) if any of their sources still contains
  `sorry`/`Admitted`/`axiom` (`count_unclosed`).
- The guard applies to **both tiers uniformly** (tier 2 today imports only Mathlib, so it is vacuous,
  but the rule must not depend on that staying true).
- The imported sources' sha256 hashes are recorded in the row's `artifacts.imports`, **plus the imported
  olean's hash/mtime and the `lake build` exit status**, so "the import was clean and the olean was
  current" is evidence, not assumption — the repl loads the olean, not the source, so a source hash
  alone does not show what was loaded. Pinned by a scenario.

A tier-1 run before the tier-2 promotion is therefore **doubly blocked** — the guard refuses (exit 2)
and the excerpt hides the import's still-`sorry` `mutex` (marking `assisted`) — the correct direction;
the promotion step (D10) unblocks it.

### D14 — What the loop shows the model (the prompt)

The model is shown, each turn: the **seed's definitions** — `State`, `Reachable`, `Mutex`, `Init`,
`Next`, and the transition relation — the specification, which §11 decision 5 already calls human
translation work; the **statement under test** (the goal); the **tactic history**; and the repl's
**per-turn refusal reason** (the driver's `proof.failures`). It is **not** shown any invariant or
helper-lemma statement — supplying one marks the run `assisted` (§11 decision 5). The prompt content is
fixed and recorded, so a reader can judge the run; without the definitions the model guesses lemma
names blind and the theorem is unprovable in principle.

### D15 — The committed seed baseline, re-seed, and what the excerpt shows

- **Immutable baseline + re-seed.** The committed `sorry` seed is immutable; its sha256 is recorded in
  `proofs/lean/token-ring/seeds.json`, and the pristine text is committed at
  `proofs/lean/token-ring/baseline/<file>`. Each run writes its per-run working copy **from
  `baseline/<file>`** (never the on-disk seed, which the legacy in-place code could have rewritten) — so
  `--reps N > 1` and re-runs start fresh, and the seed is always restorable. A drifted on-disk seed
  records `baseline.matches = false` and `assisted: true` (caught, not shown). The "0 goals at start"
  crash gets its own exit code (`seed_already_closed`), distinct from a legitimately unclosed artifact.
- **Excerpt scope (D14, made precise).** The excerpt shows the definitions (non-proof declarations'
  statements) plus the `theorem`/`lemma`/`axiom` statement *types* whose proof body is complete (no
  `sorry`/`?ident`); a `sorry`/`?ident` body is hidden and marks `assisted`. A proved statement in a
  local import is the **prior run's result** (`assisted: false`), not helper work. The row records
  **what it showed** — `row["prompt"] = {"sections": […], "shown": <per-source/per-declaration inventory>}`
  with no `withheld` key, so "no helper-lemma statement was shown" is derived from `shown`, never
  asserted. `where`-form and `example` handling must never produce a malformed fragment.
- **Seed split (driver mechanics, load-bearing).** The seed's goal is its **last declaration**; the
  driver feeds the seed as a **prelude** `cmd` (no `env`, so `import` is allowed) followed by the goal
  command with `"env": <prelude's env>` — so the goal resolves against the file's own declarations.
  Feeding the whole file as one `cmd` creates a fresh environment and leaves the goal stated in
  unresolvable constants (the P0 that rig-limited attempts 1–2). `Prover.cmd()` threads `env` the same
  way; the `responder` seam models the prelude/goal split.
- **Promotion gate (D19 provenance).** `promote.py` promotes the loop's own additions — a declaration the
  artifact *added* is the model's guessed helper, proved and hole-free, so it is the loop's work and
  promotes **unassisted**; a rewritten statement or a changed `def` value still refuses. Because a human
  can touch the tree between the run and the promotion, the gate establishes provenance from the **run's
  row**, not the file alone: it verifies the artifact against the artifact hash the row recorded at run
  time and refuses on any divergence (a human-touched artifact), rather than blanket-refusing every
  added declaration.

### D16 — The refutation arm: racing the proof arm under one budget

Route B runs **two arms in one loop, one shared 2 h/$50 budget**:

- **Proof arm** (as before): proposes tactics via the `tactic`/`proofState` channel.
- **Refutation arm**: proposes *refutations* via the repl's **`cmd` channel** — command mode runs
  arbitrary Lean commands through the elaborator, so `#eval`, `#check`, `#reduce`, and
  `example … := by decide`/`by native_decide` all execute there; the response carries `messages` (the
  `#eval`/`#check` output) and `sorries` (empty when an `example` closed) — verified against
  `tools/repl/README.md:9-39` and `REPL/JSON.lean:124-129`.

**The witness is machine-checked against the goal, never a model claim.** The harness wraps the model's
proposal in the goal's negation — `example : ¬ (<goal>) := by <proposal>` — so **Lean itself** judges
the refutation: the driver's verdict is `refuted == (env present and no error-severity message and
no/empty sorries)`. The refutation payload is prefixed with `set_option autoImplicit false` so a typo'd
name *errors* (a rejection) rather than silently auto-binding into a vacuous lookalike; an **absent**
`sorries` list is empty, not a hole (the repl omits it via `Json.nonemptyList`). This subsumes all three
forms: an explicit witness (`by exact …`), a bounded-instance enumeration (`by decide` / `by native_decide`),
and a proof of the negated statement. Anything else — an errored command, an example with `sorries != []` —
is a **rejection** (the arm keeps searching). The arm is falsifiable both ways: a refutation against a
statement TLC says holds is a rig defect (`error`, loud) — the mirror of the mutant-closed defect (§5).

**Race mechanics.** The loop alternates arms — even turns are proof (tactic), odd turns are refutation
(`cmd`) — and the prompt names the arm ("propose a tactic" vs "propose a refutation"). One model, one
shared 2 h/$50 pool; each turn is billed to its arm, and per-arm turns/tokens/cost are recorded. The
race ends as **`success`** (proof arm closed), **`refuted`** (refutation arm produced a machine-checked
witness), or **`timeout`** (neither before the budget); `error` for failures and rig defects.

**Outcome vocabulary and §2's "settled".** For the positive statement the expected outcome is `success`,
with the refutation arm's failure to find a witness recorded as corroboration. For the mutant the
expected outcome is `refuted` (an informative success), and `negative_control.observed` reflects it
(`refuted`, or `fail_to_close` if the arm found nothing before the budget). A refutation of the mutant
**counts as the mutant failing as predicted** (§5) — stated, not assumed.

### D17 — The setup is a recorded parameter

Every Route B row carries the **setup** that produced it: model selector + thinking level (already),
prompt version/sections (already), **arm configuration** (`arms: "proof" | "proof+refutation"`, the
refutation command templates), and any other varying knob — so iterated runs are distinguishable, not an
incomparable pile. The **headline** configuration (one model, fixed thinking level, `proof+refutation`)
is fixed and recorded; exploratory runs carry `exploratory: true` and are never pooled with the
headline. A genuine model matrix would be a protocol amendment to decision 2, not an implied change.
Every Route B row also records a **harness revision**: a digest of the harness sources the run imports
(`harness/*.py`) plus the data files the prompt reads (the examples file, the seed, the baseline record),
computed at run start — so a row is attributable even while the tree is dirty (two slices uncommitted)
and an iteration comparison cannot silently mix code versions.

### D18 — Cheap iteration

A re-run is cheap and clean: the seed is re-written from the committed baseline (D15), the row is
appended, and stale `.runs/<stem>-r*.lean` copies are **swept at the start of each invocation** — so at
most one invocation's copies exist and the just-finished artifact survives for the promotion step (a
copy deleted on append would leave nothing to promote). Abandoned-setup rows are labelled `exploratory`
(D17); stale oleans are irrelevant (each run's `lake build` re-establishes them). The two arms **always
run together** (the user said "run in parallel"), so there is no automatic follow-up arm — a negative
tier-2 result is the race's `timeout`, with the refutation arm's own outcome recorded beside it.

### D19 — The proof-strategy upgrade (execution skill, plus an invitation to hypothesise)

**Post-mortem, written down.** The tier-2 failure was **invariant invention**, not missing definitions
and not tactic fluency: `mutex` is not inductive as stated — `Enter i` (token `s.token = i`, `wait → crit`)
would yield two critical nodes from a state whose unreachability *is the theorem* — so the induction
hypothesis `Mutex s` is too weak, and closing tier 2 requires a strengthened statement.

**The boundary (user's ruling): invite the *activity*, never the *content*.**

- **Permitted — invite the activity.** A planning step whose schema has a **slot for the model's own
  candidate** strengthening or helper lemma, with neutral wording that invites a *guess* ("if the
  statement as written resists, you may introduce a helper lemma or a stronger statement; state any you
  intend to use"). Prompt wording that a proof may need an auxiliary invariant or a strengthened
  induction hypothesis *in general* (the activity, not the content). Few-shot examples that demonstrate
  the *move* on a **different** system (strengthening is a legitimate technique), each checked not to
  reveal token-ring's.
- **Forbidden — never the content.** The correct invariant for token-ring or any hint of it ("a critical
  node holds the token", that `Enter` is the breaking case, a candidate list, an example isomorphic to
  token-ring's proof). The model must *reach* the strengthening, not recognise it; in doubt, leave it out.

**Labelling — the experiment's central distinction.** A helper or strengthened hypothesis the **model**
produces is the loop's own work: `assisted: false`, recorded in `auxiliary_invariants` with its size
(§4.9), and the row lets a reader tell how it was obtained — model-guessed vs human-supplied. A
**human**-supplied invariant is `assisted: true` and reported separately. A guessed invariant must be
**proved** by the loop as a helper to earn anything; an unproved or false guess is recorded as a
**rejected attempt** (its statement kept — informative about the search), never silently dropped. The
loop may carry **several** candidates over a run (proposed, proved, or abandoned), one active at a
time, all recorded.

The upgrade:

1. **Few-shot examples teach tactic technique**, and may include a *different-system* strengthening
   example (the move, never token-ring's). Also: induction over an inductive reachability predicate,
   case analysis on a disjunctive transition (`rcases`/`cases`), `simp`/`omega`/`aesop`/`simp_all`
   finishing, `Finset`/cardinality handling. Each is checked against the line (a technique, never the
   token-ring insight), versioned and recorded in the setup (D17).
2. **Search tactics are named, automation auto-tried** — the prompt names `aesop`/`simp_all`/`omega`/
   `exact?`/`apply?`; the loop runs a cheap automation pass before asking the model and **records when
   automation closed a goal, and with what** (§5 vacuousness guard).
3. **A planning step per arm, one per run**: the model states its approach in neutral slots
   (`approach`, `steps`, `expected end state`, plus the neutral candidate slot), recorded **verbatim**
   (`plan.proof` / `plan.refutation`); the refutation arm gets the same affordance. An empty plan follows
   D11's empty-reply path (consumed turn, re-asked with the nudge).
4. **`assisted` for human work only** (§8, fixed below): a human-supplied invariant is `assisted`; a
   model-guessed one is not.

**Consequence and rig-limitation record.** Attempts 1 and 2 are **rig-limited, not capability
measurements**: the driver fed the seed as one `cmd` (a fresh environment, so the file's declarations
were absent), the goal was stated in constants the tactic environment could not resolve, and no tactic
could progress. Attempt 2's refusals show the model independently proposing the correct auxiliary
invariant and `Reachable.rec` with the right motive, which the rig rejected as an unknown constant — so
**no conclusion about the model, the prompt, or invariant invention may be drawn from either row**.
Attempt 3 is the first run that can act on the goal at all. The earlier expectation that an unassisted
tier-2 run "may well `fail_to_close` because the invariant is needed and we neither supply nor suggest
it" is therefore **untested, not supported** — the model reached for the invariant unprompted in a run
whose every tactic was rejected for a rig reason. A later close (or a later failure) under the fixed rig
is the first real evidence, reported as such. The assisted variant (a human supplying the invariant)
stays **out** unless the user commissions it.

### D20 — OMP as the model-call transport (replaces the raw client)

The `Model` port (`propose`/`plan`/`refute`/`usage`/`cost_basis`) is unchanged — only the transport
behind it moves, so the loop, the contracts and the scenarios are untouched (scenarios use
`ScriptedModel`). The raw HTTP client and its hand-rolled tariff arithmetic are **deleted** (one
transport, not two): OMP owns credentials, cost accounting, and provider routing/fallback.

- **Transport**: one persistent `omp --mode rpc` session (JSON-RPC over stdio). The coder **probes the
  real stream once** to verify it carries token counts, the resolved model, and a cost figure or the
  usage block, and records what it found; if RPC is heavier to drive, fall back to per-turn
  `omp -p --mode json`.
- **Cost**: extracted from OMP's recorded `usage.cost` (§11 decision 7: tokens "as recorded in the
  session's `usage.cost`"), never re-derived from a price catalog. If no cost field is present, tokens
  are priced with a single documented basis, and `cost_basis` says which.
- **`resolvedModelIsFallback`**: compares the selector against what OMP reports it actually served per
  turn, as today.
- **Setup (D17)** additionally records the invocation: the `omp` version, the model selector, the
  thinking level, and the flags the turn used — so a row is attributable to the exact call shape.

## Known limits (recorded, not checked from the tree)

- **`proof.thinking` records intent, not what was served.** The selector is attested by the echoed
  model id in each response, but whether `reasoning_effort` is the field this DeepSeek model honours
  cannot be verified from the tree — if it is ignored, `proof.thinking` records what we asked for, not
  what the model did. Flagged; the selector's attestation does not extend to the thinking level.
- **The rate card / tariff windows** are published prices that cannot be checked from the repository;
  the row's `cost_basis` string is the recorded evidence.
- **`results/proof.jsonl` has a schema boundary** at the first fix round: the retained first observation
  carries the pre-fix field set (`artifacts.artifact`, `tool.repl` as a bare string,
  `proof.empty_content_exhausted`); post-fix rows use `artifacts.proof`, `tool.repl` as an object, and
  `proof.empty_turns` (replacing the dead `empty_content_exhausted`). Record this boundary (a note or a
  `schema` field) so analysis does not KeyError on row 1; `artifact_unclosed_goals` means "holes after
  the run", not "holes the run left".
- **Stub-argued, not run-verified:** the tier-1 `decide`-style step-timeout risk and the mutant flip were
  argued from stubs while a live run was executing; whether Lean errors on an out-of-date olean or
  silently loads it is a toolchain behavior outside the repo; and `tools/repl`'s recorded commit comes
  from `PROVENANCE.md` (the checkout has no `.git`).
- **D13 textual-guard gap (known limit):** a `sorry`/`?ident` inside a `s!"{…}"` string interpolation can
  pass the textual `count_unclosed` (the strip set does not match braces). The driver's structural
  `proofStatus` close-guard covers the artifact, but D13 applies the textual count to an import's
  *source* with no repl verdict — recorded as a known limit, not silently accepted.
